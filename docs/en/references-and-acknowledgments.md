# References and source attribution

[简体中文](../zh-CN/references-and-acknowledgments.md) · [Documentation home](index.md)

## Source attribution

Ontotect builds on the accumulated work connecting philosophy, knowledge representation, software engineering, standards, domain practice, and open tooling. The bibliography recognizes the books and papers studied, W3C and other standards communities, and the maintainers of Protégé, ROBOT, ODK, OWLAPI, Apache Jena, Eclipse RDF4J, pySHACL, Ontop, WIDOCO, OOPS!, the Agent Skills specification, and host documentation.

[virgiliojr94/book-to-skill](https://github.com/virgiliojr94/book-to-skill) provided a practical open project reference for organizing a large research corpus into an Agent Skill. Its generated-skill scanner and static host lenses were also used during local verification. The public Skill Creator guidance supplied the structural conventions used by the package.

The construction research collection was read locally. The public repository carries original synthesis and citations; it does not redistribute that private collection or its extracted full text.

## Citation and evidence policy

References below use a compact APA-style form: author or standards body, year, title, container or publisher, and a DOI or authoritative project link. “Used” means a source contributed a method, distinction, test, tool boundary, packaging rule, or review criterion. It does not turn every statement in a source into an Ontotect rule.

The detailed evidence register—including page counts, the complete 29-file local corpus, authority boundaries, standards status, and wider Web research—is [sources.md](../../ontotect/references/sources.md). That register is the comprehensive source map; this page is the readable bibliography.

## Tools and ontology projects

- [Protégé](https://protegeproject.github.io/protege/) — interactive OWL authoring, reasoning, explanation, and inspection.
- [ROBOT](https://robot.obolibrary.org/) and Overton, J. A., et al. (2019), *ROBOT: A tool for automating ontology workflows*. [https://doi.org/10.1186/s12859-019-3002-3](https://doi.org/10.1186/s12859-019-3002-3).

- [Ontop](https://ontop-vkg.org/guide/) — virtual knowledge graph and mapping practice.
- [WIDOCO](https://dgarijo.github.io/Widoco/) and [OOPS!](https://oops.linkeddata.es/) — documentation and pitfall detection, used within their declared limits.
- [DOLCE](https://www.loa.istc.cnr.it/index.php/dolce/), [BFO 2020](https://bfo-ontology.github.io/BFO-2020/), [OBO Foundry](https://obofoundry.org/principles/fp-000-summary.html), [Ontology Design Patterns](https://ontologydesignpatterns.org/wiki/Main_Page), [SSSOM](https://mapping-commons.github.io/sssom/), and [OAEI](https://oaei.ontologymatching.org/) — foundational, governance, pattern, mapping, and alignment resources.
